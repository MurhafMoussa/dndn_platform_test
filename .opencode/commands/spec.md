Analyze the requested feature.

Do not write application code.

Inspect the existing repository first.

Create:

specs/<feature>.spec.md

The specification must contain:

1. Problem
2. User stories
3. Functional requirements
4. Non-functional requirements
5. Data requirements
6. Offline-first behavior
7. Failure scenarios
8. Acceptance criteria
9. Testing requirements

Do not invent requirements that were not requested.

If something is ambiguous, list it under "Open Questions".

Stop after creating the specification.
