Analyze the requested feature.

Do not write application code.

Inspect the existing repository first.

Create:

specs/<feature>.spec.md

The specification must contain:

1. Problem
2. User stories
3. Functional requirements
4. UI/UX requirements
5. Non-functional requirements
6. Data requirements
7. Offline-first behavior
8. Failure scenarios
9. Acceptance criteria
10. Testing requirements
11. Open Questions

Do not invent requirements that were not requested.

If something is ambiguous, list it under "Open Questions".

Do not invent visual requirements that were not requested or can be inferred from the existing design system.

When the existing application already defines a design pattern, prefer that pattern over inventing a new one.

Stop after creating the specification.
